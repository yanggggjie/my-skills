# pretty-md

## 1. 目标

把内容整理成层次分明、便于扫读的 Markdown。

先分清内容块和从属关系，再排版。只调整结构和措辞，不改变事实、观点、命令、路径、字段、代码及用户要求保留的原话。

---

## 2. 处理步骤

1. 找出文档主题。
2. 按不同意思划分内容块。
3. 判断内容块之间是同级、从属、顺序还是对照关系。
4. 按固定层级排版。
5. 检查编号、缩进和分隔线。

用户只问如何表达时，给出结构建议；用户要求整理或美化时，直接交付完整 Markdown。

---

## 3. 层级规则

1. 内容分块
    - 一个内容块只表达一个中心意思。
    - 不同主题必须分开，不把无关内容塞进同一段。
    - 需要独立查找的主要内容块使用 `##` 标题。
    - `##` 以下的从属内容使用列表表达，不再使用标题。
    - 并列内容使用列表，连续操作使用有序列表，对照内容使用表格。
2. 标题与编号
    - 整篇文档最多使用两级标题，只允许唯一的文档标题 `#` 和章节标题 `##`。
    - 禁止使用 `###`、`####`、`#####`、`######`。
    - `##` 使用 `1.`、`2.`、`3.` 连续编号。
    - 原本属于三级及以下的内容改为列表项，不编号。
    - 不用粗体、引用或其它格式模拟标题。
3. 严格缩进
    - `##` 下的直接内容不缩进。
    - 从属内容每深入一级，整体增加四个空格缩进。
    - 列表项包含正文、子列表、引用、代码块或表格时，这些内容全部相对该列表项缩进四个空格。
    - 后续所有从属内容必须保持所属层级的缩进，不能只缩进首行或第一项。
    - 同一层保持相同的列表形式和缩进。
    - 引用中的正文、空行和列表都必须保留对应层级的 `>`。
    - `>` 只用于引用，不用于普通内容缩进。

    ````markdown
    ## 1. 准备

    1. 材料
        准备以下文件：

        - 配置文件
        - 数据文件
            - 原始数据
            - 校验数据

        ```text
        example
        ```
    2. 操作
        1. 检查文件。
        2. 确认环境。

    > 第一段引用。
    >
    > - 第一项
    > - 第二项
    ````
4. 分隔线
    - 每两个 `##` 章节之间必须插入一条 `---`。
    - 分隔线前后各保留一个空行。
    - 列表层级之间不加分隔线。
    - 不添加其它装饰性分隔线。

---

## 4. 其它格式

- 普通说明使用段落。
- 并列项使用无序列表，有先后顺序的步骤使用有序列表。
- 需要横向比较时使用表格。
- 命令、路径、字段名和短代码使用行内代码，多行内容使用代码块。
- 原话、外部规则和摘录使用引用。
- 粗体只强调少量关键词。
- 只有分支、循环或多方关系难以用文字说明时才使用 Mermaid。
- 不添加目录、装饰性 emoji 或重复总结，除非用户明确要求。

---

## 5. 交付检查

- [ ] 内容已按主题和从属关系分块。
- [ ] 文档只使用 `#` 和 `##`，没有 `###` 及更深标题。
- [ ] 所有 `##` 标题编号连续。
- [ ] 原本属于三级及以下的内容已经改为不编号的列表层级。
- [ ] 每深入一级，后续全部从属内容都统一增加四个空格缩进。
- [ ] 引用内每一行都保留正确的 `>`。
- [ ] 每两个 `##` 章节之间都有一条 `---`。
- [ ] 没有用粗体或引用模拟标题层级。
- [ ] 原意和必须保持字面的内容没有改变。

默认只交付整理后的 Markdown，不解释处理过程。
