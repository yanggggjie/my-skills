# pretty-md

## 1. 目标

### 1.1 简单

删除重复，合并同义内容，压缩冗长句子并提炼概括语句；事实、观点、条件、例外和操作信息不能减少。

### 1.2 结构清晰

把文档重构为一棵内容树：

1. 根节点：唯一的 `# 文档标题`。
2. 第一层：全文的几个方面，使用 `## 1. 方面`。
3. 第二层：每个方面的具体方法，使用 `### 1.1 具体方法`。
4. 第三层：方法的具体内容，不再使用标题，改用段落、列表、表格、checklist、代码块、链接、提示块、文件树或 Mermaid。

---

## 2. 修改边界

### 2.1 可以修改

- 分类、归纳、拆分、合并和调整顺序；
- 提炼标题、类别名、主题词和概括句；
- 修正病句、重复、漏字、主语缺失和指代不清；
- 转换 Markdown 表现形式。

### 2.2 不得修改

- 不新增原文没有的事实、数据、原因、观点或结论。
- 不改变要求强度、适用对象、条件或范围。
- 不删除例外、限制、前提或失败条件。
- 不修改命令、路径、字段名、代码、配置和值。

冲突或歧义无法从材料中唯一确定时，保留原文并标记待确认。

---

## 3. 处理方法

### 3.1 简化内容

1. 删除重复表达。
2. 合并主题、条件和强度相同的内容。
3. 把长句改成更短的完整句。
4. 为每段提炼一个主题。
5. 逐项确认原文信息仍然存在。

### 3.2 重构内容树

1. 将主题归纳为几个“方面”。
2. 将每个方面拆成“具体方法”。
3. 将说明、规则、步骤和示例归入对应方法。
4. 使用连续编号；不得出现空泛的“其它”章节。
5. 第二层以下不再增加标题，用块级格式组织具体内容。

### 3.3 选择格式

按以下顺序判断；命中后使用对应格式：

| 内容关系 | 格式 | 使用规则 |
|---|---|---|
| 分支、循环、并行或回退 | Mermaid | 解释全部节点的输入、动作和输出；分支边标明条件 |
| 有先后顺序且没有分支 | 有序列表 | 达到 6 步时按真实阶段分为大步骤和子步骤 |
| 验收或完成判定 | checklist | 未验证用 `- [ ]`，已验证用 `- [x]` |
| 多对象同维度对比或稳定字段映射 | 表格 | 每列只表达一个固定维度 |
| 3 个及以上目录或静态层级节点 | `text` 文件树 | 树只表达层级；职责另用词条或表格说明 |
| 不超过 5 项的术语或单值属性 | 加粗词条 | 达到 6 项或包含多个固定字段时改用表格 |
| 无顺序的并列内容 | 无序列表 | 达到 6 项时检查能否分成至少两个有效类别 |
| 风险、前提或补充信息 | 提示块 | 按 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 选择 |
| 单一结论及其解释 | 段落 | 需要时提炼一个加粗主题词 |

### 3.4 使用字面格式

- 文件名、路径、字段、参数、环境变量、单个命令和短代码使用行内代码。
- 完整命令、代码、配置、JSON、日志、输出和可复制示例使用带语言标记的代码块。
- 外部原话或必须保持原样的摘录使用引用块。
- 需要打开的文件、章节和来源使用描述性链接；不使用裸 URL、裸路径或“点击这里”。
- 示例明确标注“输入—输出”或“修改前—修改后”，不得引入正文未定义的新规则。

### 3.5 细化格式

- **长列表**：6 项及以上且能形成至少两个类别、每类至少两项时分类；否则保留原列表。
- **长步骤**：6 步及以上且存在真实阶段或共同中间结果时分组；否则保留单层步骤。
- **主题词**：连续两句以上围绕同一主题时，可提炼 2 至 8 个汉字并加粗；独立内容块改用标题。
- **提示块**：`NOTE` 表示补充，`TIP` 表示建议，`IMPORTANT` 表示必要前提，`WARNING` 表示失败、数据或安全风险，`CAUTION` 表示难以恢复或不可逆后果。
- **示例**：只有用户要求解释修改，或没有示例就难以理解规则时保留；只要求结果时不附完整前后对照。

## 4. 交付

### 4.1 保真检查

- [ ] 重复和冗长表达已经简化，信息没有减少。
- [ ] 事实、观点、要求强度、适用范围、条件和例外没有改变。
- [ ] 命令、路径、字段、代码、配置、数值和引文保持原样。
- [ ] 没有新增原文不存在的事实、原因或结论。

### 4.2 结构检查

- [ ] 全文只有一个 `#` 标题。
- [ ] 第一层只使用连续编号的 `## 1.`，第二层只使用 `### 1.1`。
- [ ] 具体内容没有使用 `####` 或更深标题。
- [ ] 每个方面至少包含一个具体方法。

### 4.3 格式检查

- [ ] 步骤、分支、验收、对比、层级和风险使用了规定格式。
- [ ] 6 项以上列表和 6 步以上流程已经检查是否需要分组。
- [ ] Mermaid 解释了全部节点，代码块标注了语言。
- [ ] 需要访问的上下文使用描述性链接。

检查通过后，默认只交付整理后的 Markdown，不解释整理过程。
