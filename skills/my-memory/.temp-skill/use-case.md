# use case

## 选择 memory 或 progress
目标：决定本次操作属于长期记忆还是单个需求追踪
操作：
- 用户点名层级时直接采用
- 未点名时根据长期规则或当前需求信号推荐一层并等待确认
可观察结果：写入前已经明确选择 `memory` 或 `progress`

## 读取记忆或进度
目标：加载本次任务需要的现有资料
操作：
- 从 `/Users/youshiyitian/Code/wxa/memory/` 或 `progress/<slug>/` 读取相关文件
- 记录相对 wxa 根目录的召回 id
可观察结果：回复靠前包含本轮实际读取文件的 `memory-recall` 行

## 写入长期记忆
目标：保存跨需求仍成立的规则、手册或索引
操作：
- 短硬规则与索引写到外层 `AGENTS.md`
- 细则写到 `memory/<文件>.md`
- 保证同一事实只有一处权威，不记录槽位信息
可观察结果：目标文件已更新，新文件可由外层索引发现

## 建立或更新需求进度
目标：用独立 slug 持续记录单个需求的状态
操作：
- 确定 `progress/<slug>/`，读取或按模板创建 `PROGRESS.md`
- 记录仓库、git 分支和仓内路径，不记录槽位或槽内绝对路径
- 将详情放入同目录附属文件，入口反映真实状态
可观察结果：`PROGRESS.md` 已更新且需求与 git 分支绑定清楚

## 定位需求工作路径
目标：根据需求绑定的 git 分支找到本轮实际检出路径
操作：
- 运行 `/Users/youshiyitian/Code/wxa/memory/wxa-slots.sh [git分支]`
- 只采用本次 stdout 返回的路径
可观察结果：本轮使用的工作路径出现在本次脚本输出中

## 汇总需求分支的累计变动
目标：只统计该需求 git 分支直接提交引入的代码变化
操作：
- 由需求绑定确定 git 分支和基线
- 在本轮脚本返回的工作路径中运行 `git log --no-merges`、`git diff` 等命令
- 排除 merge commit 与其他分支的非直接提交
可观察结果：汇总范围只覆盖目标分支的直接提交
